## CRITICAL

### C1 [ADDRESSED] — Dashboard serves arbitrary repo files, including both `.env` files
`server.mjs:1536-1553`. Non-`/api/*` paths fall through to a static handler rooted at the repo,
guarded only by `file.startsWith(ROOT)` — and `ROOT` contains `.env`.

Verified: `GET /.env` → 200 (both secrets). `GET /core/.env` → 200 (live account, allowlist,
confirmation phrase). `GET /data/tradingview.sqlite` → 200. `GET /.git/config` → 200.

No `Host` validation anywhere in `route()` (`server.mjs:1195-1196` parses against a fixed
`http://localhost` base). **Remotely reachable by DNS rebinding.**

Fix: explicit asset allowlist or a dedicated `public/` root with no secrets; reject non-loopback
`Host`; deny dotfiles unconditionally.

### C2 [ADDRESSED - OPERATOR ACTION REQ] — `QT_CORE_TOKEN` and `QT_WEBHOOK_SECRET` are the same value
Verified identical SHA-256 (`9310722d785d0b86…`) in both `.env` and `core/.env`. The webhook secret
is shared with TradingView's cloud and traverses the tunnel in every alert body; the core token
authorizes `POST /private/v1/place-trade` on a live core. Both files are `-rw-r--r--`.

**Anyone holding the webhook secret holds the order-submission credential.** Treat both as
compromised. Rotate to two independent values and `chmod 600`.

> Operator action, not automated: rotating `QT_WEBHOOK_SECRET` requires updating the TradingView
> alert configuration, and rotating `QT_CORE_TOKEN` requires a core restart. Both disrupt a live
> session — perform while flat and outside market hours.

### C3 [ADDRESSED] — `store.getSelectedProfile is not a function` breaks every TradingView order on HEAD
`server.mjs:299`. `store` is the `TradingViewStore`; the method is on `OperatorStore`. The guard at
`:298` can never be false for a TradingView payload (`capital_per_trade_dollars` is not in the
ingress allowlist), so the line runs on every alert. The `TypeError` reaches
`processor.js:64`, where `isAmbiguous()` defaults unclassified errors to `true`.

Result: **every TradingView alert becomes `SUBMISSION_UNKNOWN` with zero broker contact** —
fabricating "an order may exist at IBKR" when the code provably never called. The deployed build
predates this line. There is currently no test that exercises `twsAdapter.placeTrade` at all.

### C4 [ADDRESSED] — Two stores key the same intent differently; the close path is dead
`broker_submissions.correlation_id` holds the Node *idempotencyKey*, not the Node UUID:

```
broker_submissions.correlation_id = tradingview:2026-07-24T18:32:00Z
signal_intents.correlation_id     = 989b6674-685f-4838-beaf-5e5d49fb142d
```

`server.mjs:860-876` asserts the opposite in a comment. Consequence: `POST /api/trades/:id/close`
returns `ENTRY_REFERENCE_NOT_FOUND` for every position — partial close and flatten cannot fire.
`test/server/http.test.js:392` seeds the fake core with the wrong shape *deliberately*, so the whole
close-path suite passes against an impossible contract.

### C5 [ADDRESSED] — Unsynchronized shared transport state defeats two safety invariants
`ibapi_transport.py:950-965`. `_refresh_positions` resets `self._positions = []` with no mutex.
Three threads reach it: reconciliation (every 5s), every `ThreadingHTTPServer` request thread
serving `/positions`, and the submission path. Only the last holds `_execution_lock`.

Corrupted reads feed:
- `_block_duplicate_exposure` (`engine.py:934`) — short read **silently permits a duplicate entry**
- `_fresh_working_exit_quantity` (`engine.py:891`) — short read **inflates the reduce-only bound**
- `_fresh_verified_long_quantity` — fails closed (safe)

Two of three directions are unsafe; both are AGENTS.md non-negotiables.

### C6 [ADDRESSED] — Strike band was never applied to 5 of 6 trades (band *bypass*, not violation)
Those alerts carried `strike_policy: {"type":"ATM_OFFSET","offset":1}`, routed to
`selection.choose_listed_strike()` (`selection.py:84-105`) — pure geometry, no quote, no delta, no
premium, no band. IWM pinned to P291 all day because spot sat near 292.

`validation.js:163-167` **requires** `target_dte` and `strike_policy` on every open. The minimal
alert schema is not merely unused — it is forbidden. That line hands contract geometry to the Pine
script author.

## HIGH

### H1 [ADDRESSED] — Sizing silently clamps to 1 contract; the ceiling depends on launch method
`QT_MAX_CONTRACTS_PER_ORDER=50` is in the **root** `.env`, read only by `server.mjs`. `core/.env`
has no such line, so `config.py:181` defaults to **1**, and `engine.py:651` does
`min(computed, 1)`.

| trade | fill | deployed | capital-implied | utilization |
|---|---|---|---|---|
| IWM | 0.46 | $46 | 10 | 9.2% |
| QQQ | 2.38 | $238 | 2 | 47.6% |
| IWM | 0.47 | $47 | 10 | 9.4% |
| IWM | 0.22 | $22 | 22 | 4.4% |
| IWM | 0.11 | $11 | 45 | 2.2% |
| QQQ | 1.29 | $129 | 3 | 25.8% |

**$493 of $3,000 authorized — 16.4% utilization.** App-spawned the core inherits 50; standalone it
is 1. A 50× ambiguity on live order size that nothing records or displays.

Related: sizing divides by **mid** while the order goes out at a marketable limit **above the ask**,
so worst-case debit can exceed the cap by half the spread. `index.html:220` documents the formula
without the ×100 multiplier the code applies.

### H2 [ADDRESSED] — Raising the ceiling alone makes economics worse; needs a premium floor
Commission was 18% of gross overall, **63% on the 0.11 trade** ($3.00 gross, $1.90 commission).
At $500 and 0.11 premium, 45 contracts costs ~$58 round trip against ~$135 TP1 gross.

Requiring commission ≤10% of TP1 gross gives **P ≥ $0.95**. Recommend `min_entry_premium = 1.00`,
which also lands inside the intended delta band and fixes tick drift (H6). At $500 / $1.00 premium
sizing yields 5 contracts, which funds all three TP tiers for the first time.

### H3 [ADDRESSED] — Quote freshness is structurally unverifiable; one order paid ~2× the market
`received_at` is stamped at *local arrival* (`ibapi_transport.py:744`), not from the exchange, and
`reqMktData` returns TWS's cached quote immediately on subscribe. The 3s staleness check therefore
measures "how long ago did I ask" — **`QUOTE_STALE` is unreachable**. `market_data_type` is
optimistically fabricated as `"LIVE"` (`:287`) before any callback, and `validate_quote` accepts
`"UNKNOWN"` too (`selection.py:19`).

Evidence: 18:20 order, limit 0.23 (implying observed ask ≥0.18), filled 0.11.

No re-validation of the quote between selection and `placeOrder`.

### H4 [ADDRESSED] — `TARGET_RANGE` candidate scan self-invalidates after ~1 second
`engine.py:962` captures `now` once before the loop; each candidate's `received_at` is stamped
after, so `age` goes negative and `validate_quote` raises `QUOTE_TIMESTAMP_INVALID`, silently
swallowed by `continue` at `:979-980`. Only candidates quoted in the first second are eligible.
That is the 18:50 `TARGET_RANGE_NO_ELIGIBLE_STRIKE` after 12.84s.

### H5 [ADDRESSED] — Take-profit ladder collapses to a single 100% exit, reported as success
`largest_remainder_allocation(1, [50,25,25])` → `{TP1:1, TP2:0, TP3:0}`. `paper-balanced-v1`
executed as *"exit 100% at +20%, stop 100% at −25%"* — a materially different strategy that caps
every winner at +20%. Trade 2 (QQQ 2.38→2.86) closed at exactly TP1; TP2/TP3 could never fill.

Verified for all 6 trades: TP1 `SUBMITTED qty 1`, TP2/TP3 and their paired stops
`SKIPPED_ZERO_ALLOCATION qty 0`.

Semantics are worse than the collapse:
- The dead `TRAIL_FRESH_BID` is written **`APPLIED`**, jumping `PENDING → APPLIED` and bypassing the
  `APPLYING` state `transitions.py:19-26` requires. "Did my trailing stop engage?" answers yes.
- `MOVE_STOP_TO_BREAKEVEN` produced **zero rows at all** — at qty 1, TP1 filling closes the position
  to `CLOSED`, dropping it from `filled_app_managed_correlation_ids()` before the transition is
  evaluated. The ledger cannot distinguish "never ran" from "never configured".
- `stopCoveragePercent` is parsed and wired but **never read by `engine.py`**.

### H6 [ADDRESSED] — Tick drift unguarded at low premium
Protection prices correctly derive from the **fill**, not the limit (verified: 0.48 limit / 0.46 fill
→ TP 0.56 = ceil(0.552)), and rounding is directionally safe. But at 0.11 premium one tick is 9% of
the position, so a 20%/−25% policy executes as **+27.3% / −27.3%** with a −36.4% stop limit. Nothing
reports the drift.

### H7 [ADDRESSED] — No entry TTL, no time-stop, no EOD flatten
The 13:52 entry **rested unfilled for 19m39s** before filling, executing a signal the app would
itself have rejected as expired four times over. `tif="DAY"` with no cancel-if-unfilled logic.

Exhaustive grep for `eod|flatten_all|time_stop|max_hold|expiry_cutoff`: **zero hits**. Protection
legs are GTC. The stop is a stop-*limit* whose limit sits below the trigger — on a 0DTE gap it can
trigger and never fill, leaving an unhedged long decaying to zero.

Also: **18 `SUBMITTED` protection legs against 9 `CLOSED` positions.** Nothing reconciles a
protection leg to `CANCELLED`/`FILLED`.

### H8 [ADDRESSED] — Queue holds stale alerts indefinitely, flushes backlog on reconnect
`findNextReady` (`store.js:270-275`) has no age predicate; `drainQueue` returns early when the core
is unready (`server.mjs:1156`). Three IWM alerts sat `READY` for up to 3.5h, then drained within 8ms
of each other at 12:42:19. The **only** thing that stopped three stale 0DTE orders was the core's
5-minute check on the far side of an HTTP hop. A 3-minute outage instead of 3.5 hours would have
executed all three.

### H9 [ADDRESSED] — `QT_CORE_STATE_DB` never expands `~`
`config.py:167-170` uses bare `Path()`. `core/.env` sets `~/.quickytrade/core-submissions-live.sqlite3`,
which resolves to a **relative** `./~/.quickytrade/...` under the core's cwd. The paper/live registry
separation that `core/.env`'s own comment depends on does not happen, and idempotency guarantees
become cwd-dependent.

`~/.quickytrade/core-submissions-live.sqlite3` is 0 bytes, mode 0644. `SubmissionRegistry` creates
its file at 0600 and immediately writes schema — **so no live core has ever created its registry.**
Live idempotency, crash recovery, and the unresolved-unknown block are untested against a real
session.

### H10 [ADDRESSED - OPERATOR ACTION REQ] — The one `SUBMISSION_UNKNOWN` was hand-resolved, and the outcome contradicts the note
```
correlation_id         = manual:b36d7e7b-…
status                 = SUBMISSION_UNKNOWN
reconciliation_outcome = CONFIRMED_NO_FILL
reconciled_at          = (empty)          <- impossible from code
```

**The note says filled. The durable outcome says `CONFIRMED_NO_FILL`,** which per `registry.py:341-380`
releases the exposure reservation. Zero rows in `broker_executions` for that `order_ref`; IBKR's

operator resolution endpoint. SQLite surgery on a live trading DB was the only exit.

**Requires operator audit against the actual IBKR trade log.**

### H11 [ADDRESSED] — CSRF on bodyless state-changing POSTs
`/api/core/process/{start,stop,restart}` (`server.mjs:1263,1275,1284`) read no body, so they skip the
JSON preflight that protects other routes. Any open site can `fetch(..., {mode:'no-cors'})` and kill
the core mid-position, stopping the sweep that maintains stops — denial-of-protection on an open live
position.

### H12 [ADDRESSED] — `PARTIAL CLOSE` fires a real reduce-only broker order with no confirmation
`app.js:507-510` → `submitPartialClose`, which validates only that quantity is a positive integer.
`FLATTEN` gets a modal plus type-to-confirm 8px away. The asymmetry is unjustified; a partial close
is also an irreversible market-hours sale.

## Verified SAFE

Worth recording, because the trading-safety core is genuinely strong:

- Constant-time auth (SHA-256 + `timingSafeEqual`, length not leaked), fail-closed when unconfigured,
  5-min replay window, 32KB streamed body cap, strict method/path/content-type on 4180.
- **Both listeners bind `127.0.0.1` explicitly**; the 4173/4180 collision guard is real.
- Persistence strictly precedes every broker call, on both sides, with restart sweeps to
  `SUBMISSION_UNKNOWN`. No retry is possible.
- **The 200-means-BLOCKED contract is handled correctly** (`server.mjs:348-370`); timeouts and
  transport throws become ambiguous, never failure-to-submit.
- DU/U enforcement is keyed off the *value*, not the variable name. Live requires all four of: exact
  phrase, live port, non-empty separate allowlist, membership. Session self-reported environment is
  cross-checked against IBKR's own `managedAccounts`. **No code path flips to live by itself.**
- **The Python core independently enforces symbol and trading-class allowlists** — a compromised Node
  layer cannot widen the tradable universe.
- Opens are long calls/puts only; every order is a tick-valid marketable limit from a validated quote;
  no market-order fallback; stops are `STP LMT`, never plain `STP`. Closes verify entry reference,
  right, and account, and bound quantity at fresh broker long minus working exits.
- All SQL parameterized across all six stores; no interpolation. Prototype pollution unreachable. No
  `eval`/`innerHTML` sinks. No path traversal.
- "Never render missing as zero" honored in the Node/dashboard layer (`items: null`, `'Unavailable'`).
- `npm test` passes clean: 53 JS + 169 Python, 0 failures.

## Recommended minimal alert schema

Max control in the app, min in the alert. `strategy_id`/`version` retained because they drive the
`QT_ALLOWED_STRATEGIES` gate and the audit trail.

```json
{ "schema_version": "1",
  "alert_id": "mystrat-IWM-P-2026-07-24T13:40:00Z",
  "sent_at":  "2026-07-24T13:40:00Z",
  "strategy_id": "mystrat",
  "strategy_version": "1.0",
  "action":   "OPEN_LONG_PUT",
```

for TradingView; keep `ATM_OFFSET` manual-only), `risk_hint.max_contracts` (already ignored),
